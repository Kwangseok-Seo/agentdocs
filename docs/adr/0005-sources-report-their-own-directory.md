# A Source reports its own directory; Entries are never merged across Sources

An Entry reachable from two Sources — the same directory reached through a symbolic link, for example — is listed under **both**, and each Source's count keeps describing the directory that Source names, because a count here is a statement about *a place* rather than about a deduplicated set, accepting that someone who has linked one skill directory into another sees that skill twice.

The rejected alternative is **deduplicating by resolved path**. It reads better on screen, but it makes one Source under-report the directory it names: on the development machine one of the two Bundle sources holds a symbolic link into the other, and dropping either row leaves a directory that contains one Entry being reported as containing none. Which row survives would also be decided by the order of rows in the source table rather than by anything about the Entries — and the survivor would be the link, not the directory the files actually live in. That is the silent-wrong-answer class this project ranks above crashes.

`CONTEXT.md` already settles the *Scope* case ("Different Scope means a different Source, so both appear"); this record extends the same reasoning to two Sources of the same Scope, which that dialogue does not cover. Marking the relationship on screen — showing that two rows are the same file — is **not** rejected, only deferred: it needs a resolved path (which can fail, so it waits for error handling) and a comparison *between* rows, which no single row of the source table can express, and there is nowhere to put the mark until the screen exists.
