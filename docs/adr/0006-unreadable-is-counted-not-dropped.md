# What a Walk could not read is counted, not dropped

> **The third paragraph of this record (what `unreadable` covers) is replaced by [ADR-0009](0009-unreadable-is-a-row-where-it-was-found.md).** A document that will not open is now unreadable too, and each unreadable thing is a row where it was found rather than only a number. The rest of this decision (counted rather than dropped, a Source that cannot be opened reported on its own line, the exit status left alone) still holds.

A Source that cannot be opened at all reports the reason on its own line and takes nothing else down with it, while a failure *inside* a Source — a directory entry the operating system will not describe, a subdirectory that will not open — leaves every readable Entry in place and is **counted**, so that `docs:3 (1 unreadable)` is a sentence this program can say, accepting a second number on the line and a `Walked` where a plain `Vec<Entry>` would otherwise do.

Both rejected alternatives were watched on screen before this was settled. **Dropping the failure** is what the previous milestone did: an unreadable `agents` directory holding one file printed `agents:0`, byte for byte identical to a genuinely empty `commands` — and the information was destroyed at the function boundary, so no amount of care in the caller could have recovered it. **Propagating the failure to the whole Source** produced the opposite error: one unreadable subdirectory under a `docs/` holding three readable files printed `docs:(permission denied)` and hid all three. A count that conceals its own blind spots and a blind spot that conceals the count are one mistake pointing in two directions.

Counted and skipped are different, and only one of them is reported. A Walk skips a great deal on purpose — a `.txt` file, a subdirectory in a Source that reads one level, a link it will not follow ([ADR-0007](0007-links-are-listed-not-followed.md)) — and none of that is counted, because the Walk looked and understood what it saw. `unreadable` means the Walk **could not look**: the entry would not describe itself, or the directory would not open. Holding to that rule is what keeps the number meaning one thing.

Failure is never reported through the exit status. A Source that cannot be read is a row with a reason in it and the process still exits 0, because a viewer that showed everything it could see has done its job. A script reading this output should decide from the rows, not from the status.
