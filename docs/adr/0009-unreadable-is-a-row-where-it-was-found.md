# What a Walk could not read is a row where it was found

Something a Walk found and could not look at — an entry the system would not describe, a directory that would not open, **or a document that would not open** — is kept as a row in the tree **where it was found**, with the reason, and the count beside a Source is derived from those rows, because a count alone never says which things it counts and a document that would not open used to be listed as an Entry whose `-` looked like a file with no description and which dropped out of every search without a word; the cost accepted is that such a document is no longer an Entry, so a Source's count of Entries no longer includes it, and that the listing prints every such row even while searching, since what could not be read could not be ruled out either.

This replaces the third paragraph of [ADR-0006](0006-unreadable-is-counted-not-dropped.md) (*"Counted and skipped are different ... Holding to that rule is what keeps the number meaning one thing"*). Its line between the two still holds and is restated here. The rest of that record — counted rather than dropped, a Source that cannot be opened at all reported on its own line, and nothing reported through the exit status — still holds.

**Skipped and unreadable are still different, and only one is shown.** A Walk skips on purpose what it looked at and understood: a file that is not Markdown, a subdirectory in a Source that reads one level, a link it will not walk into ([ADR-0007](0007-links-are-listed-not-followed.md)), and, in a Walk that descends, a directory whose name starts with a dot. None of that is a row. *Unreadable* means the Walk could not look, and there are three ways that happens: the entry would not describe itself, a directory would not open, or a file taken for a document would not open. The third covers a link named like a document that points at a directory: [ADR-0007](0007-links-are-listed-not-followed.md) has a file Source decide by the name, so it is opened as the document the name says it is, and it cannot be read as one.

**Where it was found** is the point. Inside a directory it is a row of that directory; inside a Bundle, a row of the Bundle. A Bundle whose Lead will not open is one such row in place of the Bundle, because the Lead is what names and shows it, and a Bundle whose directory will not open holds one. The screen draws each as `name (reason)` in the tree; the listing has no tree, so it prints each after its Source's Entries by its full path. The count is gathered from the rows by `Walked::unreadable` rather than kept beside them, so the number and the rows cannot disagree.

The rejected alternative is **keeping a document that will not open as an Entry and marking it**. An Entry is something that can be read ([`CONTEXT.md`](../../CONTEXT.md)): this one has no name from its frontmatter, no description, no text to search and nothing to preview, so each of those places would need its own way of saying so, and the one that forgot would say nothing — which is how the listing's `-` and the silent search came about in the first place.
