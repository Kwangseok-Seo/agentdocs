# The editor is run by the platform's shell, and the path never goes through the shell's reading of a line

`e` runs the editor that `$VISUAL`, or else `$EDITOR`, names through the platform's shell — `cmd /d /v:off /c` on Windows, `sh -c` elsewhere — and hands the file's path over outside the line the shell reads, in a variable cmd expands once on Windows and as sh's `"$1"` elsewhere, because a value of `$EDITOR` is written for a shell to read — `code` is found only as `code.cmd`, and `code --wait` is a name and a word — while a path read as part of a line can change what is run; the cost accepted is that an editor the shell cannot find is not an error but an exit code, so the screen can say only how it ended (`editor: exit code: 1`), not why. When neither variable names an editor, `e` opens notepad on Windows and vi elsewhere, as herdr does. The code is `editor::command`, and the two ways it builds a command are `through_cmd` and `through_sh`.

**Rejected: splitting the value into words and starting the first directly**, which is how herdr starts one on Windows. `Command` adds only `.exe` to a name with no extension, so `code` — a batch file — is not found, and `EDITOR=code --wait` cannot work without the user writing `code.cmd`. It would have named the cause of a missing editor exactly (`NotFound`), and that was the whole of what it offered.

**Rejected: the path on the shell's line.** cmd expands `%…%` in the line it reads, and with `/v:on` in effect, `!…!`; a file named `100%PATH%.md` reached the editor with the machine's `PATH` inside its name, and cmd exited 0. A variable is expanded once and its value is not read again, so the path arrives as it is. By cmd's own help, `/v:off` turns delayed expansion off for this run even where the registry turns it on for every run, which keeps `!` a character, and `/d` leaves out the AutoRun commands the registry can hold; neither registry setting is on here, so neither switch could be seen to matter.

The measurements — which editors and which file names were tried, and how many came through — are in the [M9 log](../learn/milestones/M9.md). Running `sh` on a real Unix is still unchecked: on this machine only Git's `sh` was available, and it was used for the tests.
