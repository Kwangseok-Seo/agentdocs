# A link is listed but never walked into

A directory entry that is a symbolic link or a junction is **listed** — as a Bundle where it stands in for a directory, as a document where its name says it is one — and is **never descended into**, so a recursive Walk enters only a directory that the entry itself reports as a directory, because a link is free to point at its own ancestor, which walks forever, or at another Source's directory, which merges what [ADR-0005](0005-sources-report-their-own-directory.md) says must never be merged — accepting that Markdown behind a deliberately linked subdirectory of `docs/` will not be listed.

The two questions that look alike are not. `Path::is_dir()` asks about the **target**: for a link whose target is gone it answers `false`, which is why a Bundle that had become a broken link disappeared from its Source's count without leaving so much as a row; for a link pointing at its own parent it answers `true`, which is how one junction turned a directory of two files into a hundred and twenty-eight rows. `DirEntry::file_type()` asks about the **entry**, and reports a link as a link whether or not its target exists — one function telling apart the two cases that one boolean had merged. The rule above is therefore written with `file_type()` in `md_files`, `md_tree` and `bundle_dirs`, and nowhere else.

The rejected alternative is **following links while remembering where we have been**: canonicalize each directory, keep the set of those already visited, refuse to enter one twice. It stops the cycle and does nothing about the escape — a link pointing out of the project still merges another directory's files into this Source — so a second guard rejecting targets outside the root would have to follow, and that second guard is this decision written at greater length. It also makes the answer depend on resolution, which is itself a thing that can fail.

Not following applies to **walking**, not to reading. A listed link is opened like any other Entry, so the one real link among the directories this program reads — a Bundle linked from one skills directory into another — is still listed, and its Lead is still read through the link, exactly as before. The same line divides the two questions a Bundle Source has to ask: *is this shaped like a Bundle* is answered by asking where the link points, which is reading, while *what is inside it* is not asked at all. A link to a plain file is therefore not listed as a Bundle, and a link that can no longer say what it points at is, because something is there and saying nothing about it is the failure this project ranks worst.
