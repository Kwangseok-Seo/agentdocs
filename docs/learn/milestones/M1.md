# M1 — Source discovery

> Roadmap: M1

## What was done

The binary now finds its sources and counts what is in them: five global sources assembled from the home directory, plus the project that contains the current directory. Project roots are located by walking up for a marker with a fallback to the current directory, and `docs/` is walked recursively. Verified in seven locations, all exiting 0.

```
$ cd ~/projects/cli-maker/docs/adr && agentdocs
skills:7
rules:19
agents:1
commands:1
agents/skills:1
PROJECT C:\Users\adman\projects\cli-maker
 root md:3
 docs:80
```

## Concepts picked up here

[[ownership]] · [[borrowing]] · [[owned-vs-borrowed-pairs]] · [[option-and-match]] · [[paths]] · [[fs-read-dir]] · [[macros-and-formatting]] · [[mutability]]

## Pitfalls actually hit

- [[macros-and-formatting]]: `println!(dir.count())` → `format argument must be a string literal`. The value goes after the comma, not inside the parentheses.
- [[paths]]: a variable name written inside a string literal (`"home_path/.claude/skills"`) was taken as nine literal characters, and the program panicked with `NotFound`. Rust has no string interpolation, and a path should be built with `join` regardless.
- [[mutability]]: a value built and never used stayed silent because its name started with `_`. The underscore had switched off the very warning that would have caught it.
- [[fs-read-dir]]: `count()` returned the right number for `rules` (19) and `skills` (7) **by luck**, and was wrong for `cli-maker/docs` — 2 against the 80 we wanted. It counts entries in one directory level, regardless of kind or extension.
- [[fs-read-dir]]: `read_dir(...).unwrap()` panicked on repositories with no `docs/` directory. For a program that reads other people's files, that is the normal case, not an edge case.

## What measurement changed

The plan was to treat the repository root as the project boundary, using `.git`. Measured against this machine, **5 of 17 project directories are not git repositories**, hiding 308 Markdown files outright — and widening the marker list to four still missed `session-seal`. A fallback to the current directory replaced the enumeration, which is what [ADR-0004](../../adr/0004-project-root-marker-then-cwd.md) records; it also retired the final paragraph of ADR-0002.

## Decisions

[ADR-0004](../../adr/0004-project-root-marker-then-cwd.md) — the project root rule, replacing the boundary paragraph of [ADR-0002](../../adr/0002-discovery-global-always-project-follows-cwd.md).

## What review caught

Two reviewers went over M1 before the first commit — one for the documentation, one for the source — both required to reproduce their claims rather than assert them. They found what building it did not.

The source reviewer built fake home directories, permission-denied folders, and looping junctions, and turned up a **blocker**: with any one of the five global sources missing, the program panics and exits 101. `~/.agents/skills` is not a Claude Code standard, so most people who clone this would hit it on the first run. The documentation reviewer re-measured every number in the repository and found that ADR-0002's "410 Markdown files" was the count of `docs/` directories only, not of the whole workspace it claimed to describe (1108).

The lesson is narrower than "review is good": **both findings were invisible to the machine it was built on.** Every path happened to exist here, and the number happened to be one this machine could produce. Correctness on one machine is not correctness.

Both were fixed before the first commit, using the `Result` forms in [[option-and-match]]. Verified afterwards against a home missing three of the five sources, a completely empty home, and a `docs/` tree containing a permission-denied directory — all three exit 0 now, and a missing source prints `(missing)` rather than `0` so that it stays distinguishable from an empty one.

## Left for later

- `session-seal` is identified as a root but shows nothing: its documentation lives in `Sessions/` and `Wiki/`, outside the project source definition. → M10 (config file)
- The remaining `.unwrap()` calls — `home_dir`, `current_dir`, the root-level `read_dir`, and each `DirEntry` — are still placeholders. None of them could be made to fire: denying read on a directory does not stop its owner from listing it, so the contrived cases all exited 0 anyway. They wait for M3 rather than being guessed at now. → M3
- Global `skills` counts `grill-with-docs` twice, because `~/.claude/skills/grill-with-docs` is itself a junction pointing at `~/.agents/skills/grill-with-docs`. Whether to deduplicate is deferred until the screen exists. → M2
- A junction cycle inside `docs/` inflates the count silently: a tree holding 2 files reported `docs:128`, exit 0. Descending needs to know which ancestors it has already visited. → M2/M3
- A junction inside `docs/` pointing outside the project escapes the boundary entirely: a tree holding 1 file reported `docs:473` by walking into `~/.claude`. The home ceiling that ADR-0004 puts on the *upward* search does not exist on the *downward* one. → M2/M3
- ADR-0003 says how each source is walked belongs in the source table, and it does not yet: every source is counted with a bare `count()`. A planted `stray-notes.txt` in `skills` and an extensionless `README` in `rules` were both counted, giving 2 where 1 was correct. → M2
