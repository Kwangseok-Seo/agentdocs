# M5 — The screen

> Roadmap: M5

## What was done

Typed at a terminal with no words, `agentdocs` now opens a screen of three panes: the Sources under their scope headings, the selected Source's Entries, and the selected Entry's file as it is on disk. `j`/`k` or the arrows move, `Tab` switches pane, a click selects, and dragging across the preview copies the text to the clipboard — with "copied to clipboard" at the end of the bottom row for two seconds.

With words, or with its output going to a pipe or a file, it prints the listing of M1–M4 instead, byte for byte as before — [ADR-0008](../../adr/0008-screen-for-a-bare-command-at-a-terminal.md). A Source's line in the Sources pane comes from the same `listing::heading` and `listing::failed` the listing prints, so the two cannot word it differently.

## Pitfalls actually hit

- [[modules]]: placement stalled twice — *"beyond frontmatter.rs and entry.rs I'm not sure"*, then, after an execution trace, *"I still don't follow"*. The split was then done and explained file by file.
- [[external-crates]]: *"What is a crate?"* — the word had been used for a whole slice without being defined.
- [[external-crates]]: the assistant said ratatui's newest release needed Rust 1.86 and that Cargo always takes the newest compatible version. `cargo add`'s own warning showed both wrong.
- [[traits]]: the assistant said a method needs no `use`; `is_terminal()` failed with E0599 two slices later until `IsTerminal` was imported.
- [[event-loop]]: the wheel moved the selection before any mouse code existed — the terminal was turning it into arrow keys.
- [[testing]]: "clicking a scope heading selects nothing" passed a broken click because the heading sat above the Source already selected.
- The assistant argued that drag-to-copy should wait for M6, since rendering would change what the preview shows, and then took it back: text read from the **screen cells** is whatever was shown, rendered or not. Only a selection past the rows in view waits, for M8.
- [[drop-and-unwinding]]: after one deliberate panic the mouse stayed captured in the shell. The next session measured it with a probe that logged every step and the console mode after each: on the normal path and on the panic path alike, the hook ran, `DisableMouseCapture` returned `Ok`, and the console mode came back to the value it started at. Three more panics, two of them with the very binary that had shown it, did not reproduce it. The cause of the one is unknown.
- [[testing]]: "a drag that began outside the preview selects nothing" sent one drag event, and a mutation that started a selection on the first event passed it.
- [[testing]]: a drag over blank rows copied `"\n"` and said "copied" — found by the author in a real terminal. The guard had been written as *nothing but blanks* and coded as *the empty string*.
- A check that could not fail: piping `2>&1 | Select-Object -First 3` in PowerShell would have cut a panic message off along with the rest of stderr. The pipe fix was re-checked without merging the streams.

## What measurement changed

**What a dependency costs.** Before ratatui was called, it already cost the build: 63 crates compiled instead of 1, a clean debug build of 6.5–8.8 s instead of 0.7 s, 172 packages in `Cargo.lock`. The binary did not grow until the loop called into it — 231 KB to 468 KB for the release build. The detail is in [[external-crates]].

**What words at a terminal should open.** Two candidates were run against this machine's corpus from inside `cli-maker`: the listing, as before, and a throwaway build that opened the screen narrowed to the words. The screen counted `skills:2/6`, `rules:5/14` exactly as the listing does, and showed only the matching Entries — but the preview starts at the top of the file, and `session-retro`'s Hit for `adr` is on line 74 of the file, in a preview 21 rows tall. The listing shows it as `74: …` under the row. The author chose the listing; ADR-0008 records it.

**A pipe that closes early.** Reading the first 40 bytes of the listing and closing the pipe ended in exit 101 and a panic from `println!`, as it had since M1. After the listing was written with `writeln!` and a closed pipe taken as success: exit 0, nothing on stderr. That Rust files Windows' error 232 under `BrokenPipe` is shown by the same number — any other kind would have come back as an error.

**Format characters, measured rather than assumed.** A note from the first session said ratatui drops zero-width characters as it writes a cell. Tested: a right-to-left override and a zero-width space in a **file** never reach the screen, and in an Entry's **name** they do — the Entries list keeps them. The test for names is in the suite marked `#[ignore]` with that reason.

**What copying a wrapped line gives.** 48 characters in a preview 38 wide copy as `one two three four five six seven` and `eight nine ten`, two lines, because the screen is what is read.

**Two rows with one name.** M4 left behind two `README` rows in one listing. Counted on this machine, `README`, `grill-with-docs` and `session-seal` each appear twice in the listing of both repositories, and each time in two **different** Sources; inside any one Source, the count is zero. The screen shows one Source's Entries at a time.

**A wide character over the border.** In a 120 × 24 terminal, the first screen in `cli-maker` has a row whose last inside column, 118, holds `스` — two cells wide — so the border cell, 119, was blanked. Found while capturing screens for 4-3, and confirmed cell by cell.

## Decisions

**[ADR-0008](../../adr/0008-screen-for-a-bare-command-at-a-terminal.md)** — only a bare `agentdocs` at a terminal opens the screen; words, or output that is not a terminal, get the listing. It cleared all three conditions: a command-line contract is costly to change once installed, "why do words not open the screen?" is surprising without the reason, and the alternative was built and compared.

Chosen without an ADR, because each is cheap to reverse: fields made `pub` only where another file uses them, rather than accessors everywhere; the wheel ignored until the preview scrolls; `rust-version = "1.87"` and ratatui 0.30.0 kept rather than raised; selection modelled on herdr's, with herdr's words and two seconds for the notice, shown at the right of the bottom row so it cannot cover the selection.

The existing records were checked against the new surface: the screen shows one Source's Entries at a time, never merged ([ADR-0005](../../adr/0005-sources-report-their-own-directory.md)); its Sources pane is worded by the functions that carry the unreadable count ([ADR-0006](../../adr/0006-unreadable-is-counted-not-dropped.md)); and nothing on the screen edits — copying reads ([ADR-0001](../../adr/0001-read-only-viewer.md)).

## What review caught

No separate reviewer during the milestone. The author found the blank-drag copy; mutation runs found two tests that could not fail; measuring found the pipe panic, the format characters in names, and the border.

After the milestone was committed, a midpoint review went over everything up to here: three reviewers — the documents, the program, the tests — each in a scratch and build directory of its own, and each required to reproduce what it reported. Two of them were handed the repository at the last *pushed* commit, which was M4; both noticed and moved to M5 before measuring, and the test count they reported, 136, is M5's.

What held: the listing is still byte for byte M4's in `cli-maker` — without words, with `adr 검증`, with `error`, and into a file; a pipe closed after 40 bytes still exits 0 with nothing on stderr; the screen survives a 0×0 and a 1×1 terminal and clicks at `u16::MAX`; the README's counts, M4's search examples and this log's test and crate counts were measured again and came out the same.

What did not:

| found | by | now |
|---|---|---|
| A repository that is not below the home directory, such as `D:\work\repo`, is "outside any project". [ADR-0004](../../adr/0004-project-root-marker-then-cwd.md) said only *at or above* home. | program | The author decided agentdocs does not look outside home. The record and the comment in `find_project_root` now say what the code, and `a_directory_outside_home_is_not_a_project`, already did. |
| With the guard that writes `PROJECT` once removed, every test stayed green: the fixture had one project Source, and `main` has two. | tests | `two_project_sources_share_one_project_heading` |
| Two `listing` tests built their expected rows by calling `row()`, so a broken `row()` broke both sides alike. | tests | The rows are written out. |
| [[drop-and-unwinding]] had no *Pitfalls hit*, though this log tags it. `CONTEXT.md` still stated two behaviours under *Flagged ambiguities* — M3 had trimmed the same thing from *Language*. | documents | Added; trimmed to what the words mean. |
| Three of M3's items marked `-> M5` never reached M4's list, and so not this one. | re-reading M3 during the fixes | Listed below. |

The two test fixes were checked the way M4's were, with the mutation put back on a copy: `if true` for the guard fails the new test, and `short(text, 4)` in `row()` fails both `listing` tests. 138 tests, one of them ignored.

Of the reviewer's 61 mutations, 55 are now caught. Of the six that are not, four are things no test pins down (listed below), one has no fixture anyone knows how to build — a directory entry that fails while its directory is being read — and one is the `unreadable` count inside `md_tree`, which is M3's item for M11. What is new there is that the fixture M3 thought needed a second platform can be built on this one: `icacls` can deny the current account the listing of a directory it owns, and the reviewer's run counted it — `unreadable=1`, and 0 with the count removed.
