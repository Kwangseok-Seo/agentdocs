# M4 — Search

> Roadmap: M4

## What was done

`agentdocs` now takes words to search for. Every word has to appear somewhere in an Entry — its name, or the text of the file behind it — for the Entry to stay on screen; each Source's count becomes *kept of total*; and under every row that stays, the first line that holds one of the words is printed as the reason, moved along when the word would otherwise be cut off. Run without words, it prints what M3 printed — byte for byte on this machine, with one deliberate exception described under *Decisions*.

The line under each row is a **Hit**, a new word in [`CONTEXT.md`](../../../CONTEXT.md). It is there because the rows alone could not answer the obvious question: every rule and every doc in that listing has no description, so without it there is no telling why `cobra` or `M10` was kept.

Two pieces of M3's list were paid off on the way: `Frontmatter::none()` and `Walked::new()` became `#[derive(Default)]`, and the search needed the file text that `load_frontmatter` had been reading and throwing away, so an Entry now keeps it.

## Concepts picked up here

## How it was built

In slices, most of them written by the author into a skeleton placed in the file, each checked before the next:

| Slice | What the author wrote |
|---|---|
| `derive(Default)` in place of two constructors | all of it |
| the search words from the command line | `.skip(1)` and `.map(\|a\| a.to_lowercase())` |
| the Entry keeps its text | the field, the two `text: None`, the move into `self.text` |
| `matches` | `terms.iter().all(\|t\| text.contains(t) \|\| name.contains(t))` |
| keep only what matches | the `filter` chain |
| `first_hit` | the closure inside `find` |
| `around` | — the author asked for it written and explained, and it was |

The judgement parts of `main` were then moved into `search_terms` and `listing` so that tests could reach them, and the review fixes went in after that. The table in [[iterators]] lists every chain the milestone ended with.

## Pitfalls actually hit

- [[iterators]]: asked to add two adapters, the question back was how an adapter is *implemented*. It is not; it is called. Seeing the finished four-line chain, with the value after each line, and the same thing written as a Go loop, is what landed it.
- A value with no reader yet has no visible purpose. `terms` was built before anything used it, and the question "what does `terms` do?" was fair: the answer was the whole flow — command line, `terms`, one yes/no per Entry, the count — traced with real values from this machine.
- Placement stalled in a `main.rs` of nearly a thousand lines, tests included: *"the file is too long to see where this goes."* A map of the file by line ranges and the skeleton inserted in place cleared it, and every later slice was handed over already placed.
- [[traits]]: deleting `Frontmatter::none()` left an empty `impl Frontmatter { }`, and the build said nothing about it. A `Debug` nothing needed was derived alongside `Default`. Both were found by reading the diff.
- `around` was the one slice the author did not write: *"I didn't understand what this piece is about."* A step-by-step trace of two real lines through it, with a `println!` after every step, was the explanation that worked.
- The first `around` always moved its window to ten characters before the term, which cut a heading that fit perfectly into `…텍처 결정 기록 (ADR)`. It was caught by reading the output, and the window now moves only when the term would be cut off.
- [[str-scanning]]: `around` converted byte offsets to characters, but counted the characters of the **lowercase copy**. See *What review caught*.
- [[iterators]]: `""` as a search term. See *What review caught*.
- The total number of Entries in the corpus was reported during the session as 107. It is 106 — seven Sources summed by hand, wrongly. Caught by the re-measuring reviewer.

## What measurement changed

**What the search looks at.** Before any code, each candidate scope was measured against the 106 Entries of this machine, run from inside `cli-maker`:

| word | name | name + description | + relative path | whole text |
|---|--:|--:|--:|--:|
| `검증` | 0 | 0 | 0 | **39** |
| `memory` | 0 | 1 | 1 | 5 |
| `adr` | 2 | 4 | 20 | 41 |
| `closure` | 1 | 1 | 1 | 12 |
| `error` | 4 | 4 | 4 | **52** |

The rules on this machine have no frontmatter and are written in Korean, so a search over names cannot find them at all. The whole text finds them, at the price of noise — `error` keeps 52 of 106 — and that price is why each row carries its Hit. It is also what chops, the project's motif for *what to show*, says it does: *"Full-text search — Search across name, description, and content"*. Whole text includes frontmatter keys the screen never shows, so `model: opus` is findable by `opus`.

**Two branches that were not needed.** `all` over no terms is `true` and `any` over no terms is `false` (measured, not assumed). The first means a run without words keeps every Entry; the second means no Hit is printed. Both halves of "no words means the M3 output" needed no `if`. One branch is left, in the count: `rules:14` rather than `rules:14/14`.

**One Hit in three did not show the term.** Cut plainly at 60 characters, the Hit's visible text contained none of the words in 9 of 21 lines for `adr 검증`, 11 of 39 for `검증`, 17 of 51 for `error`, 4 of 12 for `closure`, 2 of 5 for `memory` — long Markdown paragraphs put the word past the cut. After `around`: 0 in every case, and the lines it moved are exactly those, and only those.

**Two implementations, one answer.** The expected counts were produced first by a throwaway Python script with its own walk and its own matching; its per-Source totals were checked against the binary before anything else was trusted from it. The Rust search then produced the same numbers for every word measured — `adr` 41, `test` 33, `memory` 5, `closure` 12, `error` 52, `session` 13, `검증` 39, `skill` 9; `검증` as `rules:9/14 root md:2/3 docs:28/80`; `adr 검증` as `rules:5/14 root md:2/3 docs:14/80`.

**`error` is 52 rows and 51 Hits.** The missing Hit belongs to `0005-http-error-surface`, which has "error" in its file name and 에러 in its text: kept for its name, with no line to show.

## Decisions

No ADR. Each choice this milestone made — whole-text scope, words joined by AND, a Hit per row, lossy decoding — lives in one function and is cheap to reverse, which fails the first of the three conditions an ADR has to meet.

The existing records were checked against the new surface rather than assumed to cover it:

- [ADR-0005](../../adr/0005-sources-report-their-own-directory.md) — a search never merges Sources: `agentdocs grill` lists `grill-with-docs` under `skills:2/6` and again under `agents/skills:1/1`.
- [ADR-0006](../../adr/0006-unreadable-is-counted-not-dropped.md) — the unreadable count survives a search, including one that keeps nothing: `rules:0/2 (1 unreadable)`, pinned by a test.
- [ADR-0007](../../adr/0007-links-are-listed-not-followed.md) — `~/.claude/skills/grill-with-docs` is a junction, and its Hit is read through it: reading a file is not walking into a directory.

**One deliberate change to the no-words output.** A file holding a byte that is not UTF-8 used to show `-` for its description, because the whole read failed. It is now decoded lossily, so such a file with a description shows it. Neither this machine's corpus nor the reviewer's fixture has one, and both still print byte-for-byte what M3 printed.

## How it was verified

92 tests. The 34 added here cover `matches`, `first_hit`, `around`, `chars_before`, `search_terms` and `listing`, plus text surviving a real walk and a Bundle with no Lead having none.

**The first 77 were green while five faults in `main` went unseen.** A mutation run broke 19 places one at a time; the 14 inside functions turned the suite red, and the 5 inside `main` — search words not lowercased, the program's path taken as a word, nothing filtered, the plain count printed during a search, the Hit cut without moving — turned nothing red. Run for real, the first of those prints `rules:0/14` for `agentdocs ADR` and exits 0. The judgement in `main` was moved into `search_terms` and `listing`, the way M3 moved a row into `row()`, and the final run:

| broken on purpose | tests red |
|---|--:|
| `matches`: `all` → `any` / name not searched / text not searched | 3 / 5 / 8 |
| `matches`: text not lowercased / name not lowercased | 2 / 1 |
| `load_frontmatter` drops the text / refuses a non-UTF-8 file again | 2 / 1 |
| `first_hit`: `any` → `all` / numbered from 0 / line not lowercased | 3 / 6 / 2 |
| `around`: fit measured in bytes / skip measured in bytes | 2 / 2 |
| `around`: fit or skip counted on the lowercase copy again | 1 / 1 |
| `chars_before` counts lowercase characters instead of bytes | 4 |
| `around`: `min` → `max` / always moves / skips `printable` | 1 / 4 / 1 |
| `search_terms`: not lowercased / program path kept / `""` kept | 2 / 5 / 1 |
| `listing`: nothing filtered / plain count / unreadable dropped | 2 / 2 / 2 |
| `listing`: Hit cut without moving / no Hit at all | 1 / 2 |
| **`main` hands `listing` no words** | **0** |

The last row is the boundary, left there on purpose: tests do not run `main`, and whether an end-to-end test of the binary belongs in the repository is M11's question. `main`'s part is now two calls, and it was checked the same way throughout — the binary run in `cli-maker` and compared byte for byte, without words against M3's output, and with words against the previous run.

Two notes on measuring, both from this session. A Python patch written through a Bash heredoc lost a backslash (`\\u` became `\u`) and failed, and the measurement in the same command went on to run against the build it had failed to patch; the `SyntaxError` at the top of the output gave it away, and patches now go through a file. And a reviewer saw `rtk proxy cargo test` report a previous mutant's failures without recompiling; the cause is not known, so the mutation script now calls `cargo.exe` directly and reports any run without a `Compiling` line as stale. All 27 recompiled.

## What review caught

Two reviewers, each with its own scratch and build directory: one attacking the program, one re-deriving the session's numbers and claims by its own method.

The attacker found **four wrong answers at exit 0**, each reproduced on a fixture home:

| input | was | now |
|---|---|---|
| `agentdocs "" adr` | the right rows, each with `1: ---` as its Hit; `agentdocs ""` kept every Entry | an empty or blank argument is not a word |
| forty `İ` before the term | the Hit was `…` and nothing else; with 29 `İ`, it showed filler that did not contain the term | positions are walked back to the original line (`chars_before`) |
| one byte that is not UTF-8 | the file vanished from every search, uncounted | decoded lossily; only that byte shows as `�` |
| a word holding a line break | the Entry is kept with no Hit | unchanged, now documented and pinned by a test |

The second is the lesson worth keeping. `around` did convert bytes to characters, as [[str-scanning]] had taught since M2 — in the wrong string. `İ` lowercases to two characters, so a character count taken on the lowercase copy and applied to the original lands somewhere else, and every test passed because in every test the two had the same length.

The re-measurement held every claim but one number — the 107, which is 106 — and added six mutations of its own, all caught. It also reported that `printable` lets through Unicode format characters such as a right-to-left override — see below.

## Left for later

- **`printable` passes format characters.** `'\u{202e}'` (right-to-left override) and `'\u{200b}'` (zero width space) are not `is_control()`, so a name or description can still reorder how a row looks in a terminal that honours them. This predates M4. `std` cannot ask for "every format character", and a hand-written list is the kind of guard that misses the next one. -> M5, where the screen decides what reaches the terminal
- A file that exists but cannot be opened still has no text, so it drops out of search as silently as its description shows `-`. The M3 item, now with a second consequence. -> M5
- A word containing a line break keeps its Entry without a Hit. Documented; not worth more until someone types one. -> none
- Search reads a Bundle's Lead, not its supporting files. -> M7, with the Bundle tree
- Korean characters are two columns wide, so a 60-character Hit can be 120 columns. The description column has had the same problem since M2. -> M5
- `main`'s wiring is outside the tests. -> M11, with the end-to-end question
- Entries from a `MarkdownTree` are still named by file stem, so `agentdocs adr 검증` lists two rows called `README`. -> M5
- `Source::new` still takes `&str` and copies. -> M10
- `thiserror`, for the first place two error kinds share a channel. -> M10
