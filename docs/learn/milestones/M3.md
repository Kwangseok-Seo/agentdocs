# M3 — Error handling and the first tests

> Roadmap: M3

## What was done

Every place where the program had been guessing now says what it was told instead. Of M2's four silently swallowed failures, the three that decide whether a Source can be walked became a `Result` that travels to the row it belongs to; the five `.unwrap()` calls became either that same `Result` or a row that reports the reason; `Walked` grew a count of what a Walk could not read; and the meanings a single `false` had been carrying — *not a directory*, *the target is gone*, *I gave up resolving* — were separated by asking the directory entry instead of the target. Then the checking M2 had done by hand became 58 tests.

The fourth swallow is still there, and saying otherwise would be the kind of claim this milestone exists to stop making: a Lead that exists but cannot be read still leaves the row's description empty, indistinguishable from a Lead that never had one. The Entry knows the difference; the row has nowhere to put it until there is a screen.

The milestone is visible in one line of output that used to be two identical ones:

```
$ agentdocs        # fixture home, deliberately broken; abridged: the rows under rules: and docs: are elided
GLOBAL
  skills:3
    alpha                            first skill
    beta                             second skill
    ghost                            -                 <- a Bundle whose link target is gone
  rules:1
  agents:(permission denied)                           <- exists, holds one file, cannot be opened
  commands:0                                           <- genuinely empty
  agents/skills:(missing)                              <- no such path
PROJECT ...\proj3
  root md:0
  docs:3 (1 unreadable)                                <- three found, one subdirectory refused
```

Under M2 the third, fourth and fifth of those lines all read `:0` or `:(missing)` by way of a boolean, `ghost` was not printed at all, and `docs` was `3` with no mention of the subdirectory it never opened.

## Concepts picked up here

[[result-and-errors]] · [[file-types-and-links]] · [[testing]] · [[owned-vs-borrowed-pairs]] (the `&'static str` section)

Two things were used a milestone early and are only noted, not taught: `#[derive(Debug)]` on three types, because `unwrap_err()` requires it (traits — M4), and `&'static str`, because a function returning only literals has no argument to borrow from (lifetimes — M6).

`thiserror` was on the roadmap for this milestone and **was not used.** Every failure in the program is an `io::Error`; a custom error type would have added a layer that carried no information the `io::ErrorKind` did not already carry. The crate earns its place where a second error kind appears — the config file of M10, where a TOML parse failure and an io failure have to travel the same channel — and the roadmap has been moved to say so.

## Pitfalls actually hit

- [[result-and-errors]]: the compiler's own `help:` line proposed `Result::expect` **three times** — that is, proposed reinstating the panics the milestone existed to delete. It compiles. It is also the exact opposite of the intent, and nothing about the error message says so.
- [[result-and-errors]]: leaving `entries` as a `Result` did not make `for entry in &entries` fail as "not an iterator". `Result` *is* iterable — one item on `Ok`, none on `Err` — so the loop ran once around the whole `Vec` and the error read `no field 'name' on type '&Vec<Entry>'`.
- [[result-and-errors]]: in a recursive function the compiler types the recursive call from the **declaration**, so a body rewritten to return `Walked` while the signature still said `Vec<Entry>` produced its error twelve lines below the cause, on `out.absorb(sub)`.
- [[testing]]: `unwrap_err()` requires `Debug` on the **success** type, so three domain types had to derive it before a test about failure would compile.
- A `println!` where a `print!` was intended put `(1 unreadable)` on its own line and added a blank line after every other source. It was found by dumping the output with each line wrapped in brackets — see below for how it was very nearly missed instead.
- Naming `md_tree`'s recursion and `md_files` as separate enumerations of the same directory would have counted one failed entry **twice**, once in each. Folding the two into a single `read_dir` was not a tidiness change; it was the difference between a count that is right and one that is nearly right.

## What measurement changed

**The two lines that were identical.** An `agents` directory holding one file with read permission denied, and a genuinely empty `commands` directory, printed the same six characters. The reason was not a missing check in `main` — `md_files` returned `Vec::new()` in both cases, so the fact had already been destroyed at the function boundary and no caller could have recovered it. This is the whole argument for propagation over swallowing, and it is an observation rather than an opinion.

**The blast radius, measured in both directions.** After the first pass, a `docs/` holding three readable files and one unreadable subdirectory printed `docs:(permission denied)` — worse than M2, which at least showed the three. Neither all-or-nothing nor silence is right; the third option had to be built. See [ADR-0006](../../adr/0006-unreadable-is-counted-not-dropped.md).

**One junction, and it is not in a tree.** Across `~/.claude`, `~/.agents` and every `docs/` under `~/projects` — 15 roots, scanned recursively — there are three links: two hard links to `.jsonl` files, in a directory this program does not read, and one junction, `~/.claude/skills/grill-with-docs` into `~/.agents/skills`. There are **no** directory links inside any tree-walked source, so refusing to follow links costs nothing measurable today, while following them cost 128 rows for a two-file directory. See [ADR-0007](../../adr/0007-links-are-listed-not-followed.md).

**`e` speaks the machine's language; `e.kind()` does not.** Printed directly, an `io::Error` on this machine reads `액세스가 거부되었습니다. (os error 5)`. That would have made the program's output vary by locale and pinned no test. All display text is now built from `ErrorKind`.

**The real corpus did not move.** The sample the README has carried since M2 — this binary run inside a neighbouring repository — still reproduces exactly: `skills:7 rules:19 agents:1 commands:1 agents/skills:1 root md:3 docs:80`, 121 lines. `grill-with-docs` appears under both Bundle sources and still shows the description read *through* the junction, because not following links applies to walking, not to opening a file.

## Decisions

[ADR-0006](../../adr/0006-unreadable-is-counted-not-dropped.md) — what a Walk could not read is counted, not dropped; failure never travels through the exit status.
[ADR-0007](../../adr/0007-links-are-listed-not-followed.md) — a link is listed but never walked into.

**Unreadable** was added to [`CONTEXT.md`](../../../CONTEXT.md), because the word is now on screen and it means something narrower than "went wrong": it is what the Walk *could not look at*, as against the much larger set of things it deliberately skips.

## How it was verified

58 tests (`cargo test`), plus a fixture tree built by script for the one case `std` cannot construct.

The tests cover the pure layer end to end — `parse_frontmatter` against every case in M2's hand-run table, `short`, `printable`, `row`, `md_entry`, `reason`, `Walked::absorb` — and the fs layer through scratch directories under the system temp directory: missing versus empty, `.md` versus `.txt` versus extensionless, a directory named `oops.md`, one level versus a full tree, a Bundle with and without its Lead, a Lead that renames its row, and the five branches of `find_project_root`.

**Links are tested too, which was assumed impossible until it was tried:** `std::os::windows::fs::symlink_dir` succeeds on this account, so a linked document, a linked subdirectory that must not be walked into, a directory linked to itself, a Bundle reached through a link, a Bundle whose link target has been deleted, and a link to a file that must not become a Bundle are all built and torn down by `cargo test`. Where the privilege is absent those six print `SKIPPED` with the error kind rather than passing quietly; `cargo test -- --nocapture | grep -c SKIPPED` reported 0 here.

The fixture script builds what `std` still cannot: a directory with its read permission revoked by `icacls`. It also runs the whole binary end to end against a junction cycle, a junction escaping a project into `~/.claude`, and the three ways a Source can fail, which is a different question from whether each function behaves.

| planted | M2 | after M3 |
|---|---|---|
| Bundle that is a dangling junction | absent from the count | listed, `-` for description |
| directory that exists but cannot be read | `0` | `(permission denied)` |
| directory that is genuinely empty | `0` | `0` |
| path that does not exist | `(missing)` | `(missing)` |
| junction cycle inside `docs/` | `128` | `2` |
| junction escaping the project | `2`, a global rule shown as a project doc | `1` |
| unreadable subdirectory among three readable files | `3`, silently | `3 (1 unreadable)` |

All exit 0.

**The suite was then attacked rather than trusted.** Nine deliberate mutations against the 58 tests:

| mutation | tests red |
|---|---|
| `read_dir` failure swallowed again | 3 |
| `short()` stops filtering control characters | 3 |
| an empty declared `name:` overwrites the filename anyway | 1 |
| `bundle_dirs` stops treating a link as Bundle-shaped | 2 |
| `md_files` goes back to requiring a plain file | 1 |
| `md_tree` asks about the target again, following links | 2 |
| the name column stops being filtered | 1 |
| a dangling link is dropped instead of listed | 1 |
| **`md_tree` stops counting an unreadable subdirectory** | **0** |

The last row is a real hole and is recorded as one: `std` offers no portable way to make a directory unreadable, so **every path that increments `unreadable` is verified only by the hand-built fixture.** `Walked::absorb` is unit-tested, so the arithmetic is covered; nothing automated proves that a walk ever reaches it.

Two notes on the measuring itself, both from this session.

The first mutation run drove `sed -i 's|...|...|'` over a pattern containing `|`. The substitution was rejected, the file was never touched, and the suite reported 48 passed — which, read at face value, is a *second* hole that does not exist. The mutation script now diffs against its backup and prints `!! NOT APPLIED` when nothing changed.

Earlier, output was filtered through `Select-String '^\s{2}\S'` to hide entry rows, and the filter quietly dropped `(1 unreadable)` — a line beginning with a single space. The conclusion drawn from the filtered output was that the count was being lost somewhere between `md_tree` and the screen. It was not; the filter was.

## What review caught

Two reviewers went over M3 before the commit — one attacking the program, one re-measuring every number in the documents — both required to reproduce their claims rather than assert them, and each given a scratch directory of its own, because in M2 two reviewers shared one and each changed what the other was measuring.

The source reviewer found **four ways to produce a wrong answer at exit 0**, three of them fixed here:

| input | was | now |
|---|---|---|
| a `.md` file that is a symbolic link | not listed and not counted — it simply vanished | listed like any other document |
| a control character in a frontmatter `name:` | written to the terminal verbatim, and the column alignment broken with it | dropped, by the same filter the description already had |
| a link to a *file* sitting in a Bundle Source | listed as a Bundle | not a Bundle |
| `USERPROFILE` spelled in a different case than the directory | the whole PROJECT block disappears | **unchanged — deferred, see below** |

The first is the sharper lesson: [ADR-0007](../../adr/0007-links-are-listed-not-followed.md) says a link is listed and not followed, and only the Bundle walk had been taught that. The file walks used `ft.is_file()`, and `is_dir`/`is_file`/`is_symlink` are documented as mutually exclusive — a link is a link and nothing else — so a linked document failed the gate and fell into the same silent `continue` as an ordinary subdirectory. The record was right and the code was half of it — found by reading the two against each other, not by running anything.

It also found that **the entire link surface had no automated test**: the single mutation that reverts this milestone's headline fix passed 48 of 48. That is fixed here, and it is why the mutation table above has nine rows instead of three.

The documentation reviewer found five claims that did not hold, and the two that mattered were about this document:

- **The opening sentence contradicted the "Left for later" list four sections below it**, claiming all four of M2's swallowed failures had become a `Result` when `load_frontmatter`'s is byte-for-byte unchanged. Rewritten.
- **The sample output above was presented as a complete run and is not** — `main` prints one row per entry unconditionally, so no fixture could produce those counts with no rows. Marked as abridged, the way the README's samples already were.
- **The explanation of why the junction cycle stopped was invented rather than measured.** It said Windows' path length limit made `read_dir` fail and the swallowed error hid it. Probing the boundary showed neither half: the cutoff is the reparse-point hop count (`FilesystemLoop`, os error 1921) at a path 384 characters long, and `path.is_dir()` answered `false` before any `read_dir` was attempted, so there was no error to swallow. The corrected version is a better story than the invented one — see [[file-types-and-links]].
- `CONTEXT.md`'s new term carried a behaviour rule in its second sentence, which `CONTEXT-FORMAT.md` reserves for an ADR. Trimmed to one sentence that says what the word means.
- A quotation from the standard library's own documentation was cut eight words early inside its quotation marks. Completed.

Every other number in these documents — the 121-line real-corpus sample, all seven rows of the M2-versus-M3 table, the mutation table, the `is_dir()`/`file_type()` truth table, the localized error messages, the 15-root corpus census, and every claim about the standard library — was independently re-derived and held.

## Left for later

- **`find_project_root` compares paths case-sensitively, and Windows does not.** With `USERPROFILE` set to the same directory spelled in a different case, `start.starts_with(home)` is false, the first guard returns `None`, and the **entire PROJECT block disappears** — reproduced by running the binary twice against one fixture, changing only the case of the environment variable. It is not reachable by the shell, which normalises the current directory, and it predates M3 by two milestones. It is left here rather than patched because the fix is a decision, not a line: comparing canonicalised paths resolves links, which is exactly what ADR-0005 and ADR-0007 decided not to do, and it puts `\\?\` in front of the path the screen prints. Path identity deserves its own slice. -> M5
- **The `unreadable` counter has no automated test.** A `#[cfg(unix)]` test using `fs::set_permissions` would cover it on one platform and could not be run on the machine it was written on. The link tests added here show the shape it would take — build the fixture, print `SKIPPED` and return when the platform refuses — so this is now a matter of having a second platform to run on rather than of not knowing how. -> M11, alongside CI
- The fixture script is PowerShell and lives outside the repository. It is down to one thing `std` cannot build plus the end-to-end runs. Where a cross-platform version belongs — and whether it belongs in the repository at all — is undecided. -> M11
- A link named `notes.md` that points at a *directory* is now listed as a document, because a file Source decides by name and asking where the link points would be walking into it. Nothing on this machine does that, and the row it produces is honest (a name, no description), but it is a consequence of the rule rather than a case anyone chose. -> M5
- A per-item failure and an unopenable subdirectory both add 1 to the same counter, so `docs:80 (3 unreadable)` does not say *which* three. There is nowhere to put that until there is a screen. -> M5
- A Lead that exists but cannot be read still shows `-`, the same as a Lead with no description. The Entry knows the difference and the row does not. -> M5
- An `agents:(permission denied)` row shows no count, because there is none to show. Whether it should instead read `agents:? (permission denied)` is a question about a screen that does not exist yet. -> M5
- `Frontmatter::none()` is still what `#[derive(Default)]` gives for free. Three types now derive `Debug`, so the trait machinery is half-introduced already. -> M4
- Entries from a `MarkdownTree` are still named by file stem. -> M4 or M5
- `Source::new` still takes `&str` and copies. -> M10
- `thiserror`, moved here from this milestone, for the first place two error kinds share a channel. -> M10
