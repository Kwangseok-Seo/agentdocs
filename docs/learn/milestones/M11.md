# M11 — Distribution

> Roadmap: M11

## What was done

agentdocs can be installed without Rust. A tag builds it for five targets, runs each binary, tries both install scripts on what it built, and only then publishes a GitHub release:

```
$ curl -fsSL https://github.com/Kwangseok-Seo/agentdocs/releases/latest/download/install.sh | sh
agentdocs: downloading agentdocs-x86_64-unknown-linux-musl.tar.gz (latest)
agentdocs: installed agentdocs 0.1.0 as /root/.local/bin/agentdocs
agentdocs: /root/.local/bin is not on your PATH; add it in your shell's profile: export PATH="/root/.local/bin:$PATH"
```

That run is the script on Debian, against a release laid out as GitHub serves one and served from a container beside it; the address in the first line is the one it will be fetched from once the repository is public, which no run has used yet. `install.ps1` does the same in PowerShell 5.1 and 7, and adds its directory to the user's `PATH`. Each checks the archive against `SHA256SUMS` first:

```
agentdocs: downloading agentdocs-x86_64-unknown-linux-musl.tar.gz (vbad)
agentdocs: agentdocs-x86_64-unknown-linux-musl.tar.gz does not match its checksum; nothing was installed
```

The release itself was tried twice, as pre-releases deleted afterwards. The second, `v0.1.0-rc.2`, ran every job to the end:

```
build (x86_64-unknown-linux-musl)    success      try-installers (ubuntu-latest)    success
build (aarch64-unknown-linux-musl)   success      try-installers (macos-latest)     success
build (x86_64-apple-darwin)          success      try-installers (windows-latest)   success
build (aarch64-apple-darwin)         success      publish                           success
build (x86_64-pc-windows-msvc)       success
assemble                             success
```

and published eight files: five archives of 1.5 to 1.8 MB, `SHA256SUMS`, and the two scripts. Downloaded here, every checksum matched; the Windows binary said `agentdocs 0.1.0-rc.2` and loads no `vcruntime140.dll`; both Linux binaries ran on Alpine, the aarch64 one under qemu.

The binary says what it is now, rather than searching for the words:

```
$ agentdocs --version
agentdocs 0.1.0
$ agentdocs --help | head -1
agentdocs 0.1.0 — A terminal viewer for AI agent skills, rules, and docs
```

And it was run on Linux and macOS for the first time — the tests on every push, on three systems — which changed four things the user sees, none of which had shown on Windows:

- **Rows are in order of name everywhere**, as a file manager orders them: case ignored, a number read as a number. On Linux they had come in the file system's hash order. Here the listing is byte for byte M10's in 69 of 75 runs; in the other six, the milestone logs are in order:

  ```
  $ cd agentdocs && agentdocs M1 | more        # abridged
      M1                               -
      M2                               -
      ...
      M9                               -
      M10                              -
  ```

- **A home reached through a link finds its projects.** Unix reports the current directory with links resolved, so with `HOME` written through one — FreeBSD's `/home` is a link — every project was `(outside any project)`, exit 0.
- **A Bundle shut to its owner says `permission denied`**, where on Unix it said it had no SKILL.md.
- **A screen that cannot watch still opens.** On Linux, with every inotify instance its user may have taken, it had ended with `Error`, exit 1, before drawing; now it opens, and the bottom row says `not watching for changes`.

## Pitfalls actually hit

All of them the assistant's; each is written up where the concept lives:

- [[platform-differences]]: a test that had only ever run on NTFS, and read its rows in NTFS's order; a fixture that made one situation on Windows and another on Unix; `is_file` answering "no" for a path it was not allowed to look at; a test expecting Windows' word for a reason.
- [[testing]]: a test run in a container used a build left there by a mutation of other code, because `tar` restored each file's time and cargo decides by time.
- [[continuous-integration]]: rc.1's Windows installer run checked a spelling of `PATH` rather than a property of it; and one failing installer run cancelled the next one's answer.
- Writing this log's pages, a backslash in `\\?\`, passed through a Python string in the shell, came out `\?\`; it was caught reading the page back.

## What measurement changed

**The release profile.** Six were built from clean, on Windows and for x86_64 musl, and timed on a search; the table is in [[release-profiles]]. Fat link-time optimisation, one codegen unit and stripping made the binary 8% smaller on Windows and 29% on Linux, for three times the build. `opt-level = "s"` made a search twice as slow, and `panic = "abort"` saved 4% on Linux at the price of `Drop` on the way out: both were left.

**The Windows C runtime.** The binary built with the defaults imported `vcruntime140.dll`; with `+crt-static` it imports only system DLLs, and is 0.1 MB larger.

**Order.** NTFS already kept names in nearly this order; the sort reads numbers as numbers, and lowercases where NTFS uppercases, which puts a `_` before the letters rather than after them. Against M10's binary, both run at the same moment in 75 places — at home and in every project, bare, with `adr`, with `검증` — 69 were the same bytes and 6 the same lines in another order, every one of them a milestone log. Slices 2 and 4 were each compared with the slice before: the same bytes in all 75. The final binary against M10's gave slice 1's 69 and 6 again.

**What it costs to run.** The first CI run took 3 minutes on Linux, 1 on macOS and 8¾ on Windows; with cargo's builds kept between runs, under a minute and a half on each. On a private repository a Windows minute counts twice and a macOS minute ten times — about 45 counted minutes for the first run.

## Decisions

One record was written. [ADR-0013](../../adr/0013-releases-come-from-a-tag-and-the-installers-are-tried-first.md): the archive names and the `releases/latest/download/` addresses are what install scripts and people's own scripts fetch by, from the first release on; the scripts are assets of the release they install; Linux binaries are static against musl; the release waits on the installers; and crates.io, package managers and a manifest of our own were set aside, each for a reason.

- **Chosen by the author**: no quizzes in M11, a report after each slice; a commit and a push after each slice; the release tried with a pre-release tag and deleted after; the screen looked at once every milestone is done, before the repository is made public.
- **Chosen by the assistant and reported**: the five targets — herdr's; musl for Linux, built on x86_64 with a cross linker and run under qemu; Intel macOS built on Apple silicon and run under Rosetta; archives named by target triple, holding the README and both licences; install scripts as release assets, checking `SHA256SUMS`, installing without an administrator, `curl` or `wget`, `AGENTDOCS_VERSION` and `AGENTDOCS_INSTALL_DIR`, and on Windows `AGENTDOCS_NO_MODIFY_PATH`; the user's `PATH` appended to as stored; actions pinned by commit; `SKIPPED` failing CI; `rust-version` tested; clippy with warnings as errors, after one line's three warnings; no `rustfmt` check — 318 places differ, and reformatting every file would bury what was learned where in a diff of whitespace; the release profile; rows ordered as a file manager orders them, rather than byte order, which would have put `M10` before `M2` here as NTFS did; `--version`, `-V`, `--help` and `-h` taken out of the search words, and no others; a home behind a link asked again resolved, only when the path as written finds nothing; a screen without a watcher kept open, and saying so.

The records were checked against what M11 added. [ADR-0007](../../adr/0007-links-are-listed-not-followed.md): what makes notify not watch through a link was untested anywhere until a test of it ran on Linux. [ADR-0008](../../adr/0008-screen-for-a-bare-command-at-a-terminal.md): four arguments are no longer words; neither the screen nor the listing is what they print, and a bare command, words and a pipe still choose as before. [ADR-0004](../../adr/0004-project-root-marker-then-cwd.md): the root is still found by walking up for a marker below home; home is now also compared as its links resolve. [ADR-0011](../../adr/0011-changes-are-heard-not-polled.md): with no watcher, nothing is heard, and the screen says so rather than pretend.

## How it was verified

346 tests here and 9 of the binary, none ignored; 345 and 9 on Linux and macOS, where two of Windows' tests of cmd are not compiled and one of a directory shut entirely is. At the end of M10 there were 340, and on Linux one of them failed.

| slice | broken on purpose | caught |
|---|---|--:|
| 1 | no sorting; one Walk or another not sorted; digits compared as text; leading zeros counted; case counted; no tie-break; a shorter name not first; on Linux, the Lead taken for none when it could not be looked at | 9 of 9 — 7 of 8 at first: a name that begins another passed, until the test held one |
| 2 | `write_listing` where `main` calls `print_listing`; project Sources left out; either config file never read; the current directory taken for the root, or for home; `--version` never asked; version before help; flags searched for; the program's path taken for a flag | 10 of 10 — the closed pipe on Windows and on Linux |
| 7 | on Linux, notify told to follow links | 1 of 1 — 0 until a test changed a file behind one |

Each install script was run against a stand-in release: `install.sh` on Debian with `curl`, Alpine with `wget` and busybox, and Alpine on arm64; `install.ps1` under PowerShell 7.6 and 5.1, with `PATH` left alone. For latest and for a tag it installed a binary that said its version; for a tampered archive and for a `SHA256SUMS` without its line it stopped, exit 1, and installed nothing. `shellcheck` found nothing in `install.sh`. What changes `PATH` was run only on GitHub's Windows runner, which is thrown away after.

The screen without a watcher was run on Linux in a pseudo-terminal, after another program took all 8190 inotify instances its user could have: before the change, exit 1 and 235 bytes drawn; after, exit 0, the screen, and `not watching for changes`; with the instances free, no such words.

New:
