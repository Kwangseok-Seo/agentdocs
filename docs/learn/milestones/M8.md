# M8 — Scrolling, and code in colour

> Roadmap: M8

## What was done

The preview scrolls. Over it, the wheel moves three rows a notch; `Tab` now goes round three panes, and in the preview `j` and `k` move a row; Page Down and Page Up turn a page of it from any pane. Each file is left where it was scrolled to, and found there again. When a file has more rows than show, the title says which: this repository's `lifetimes` page, scrolled to its first block of Rust —


Code is coloured by what each piece of it is, in the terminal's own colours, so a light palette and a dark one both keep their contrast. The same rows, read cell by cell with their indentation left out, and every colour that is not the terminal's own text colour named after its run:

```
## A name says which input an output borrows from[Cyan]

fn[Magenta] longer[LightBlue] (a: &str[Magenta] , b: &str[Magenta] ) -> &str[Magenta] {
if[Magenta] a. len[LightBlue] () >=[Magenta] b. len[LightBlue] () { a } else[Magenta] { b }
}
error[E0106]: missing lifetime specifier[Yellow]
  = help: this function's return type contains a borrowed[Yellow]
…
```

The block of Rust is coloured; the compiler's output under it, fenced with no language, is yellow as all code was before. A comment would be dark grey, a string green, a number light red. What no kind of token covers — `a`, the brackets — is in the colour of the text around it. A block of Markdown is yellow whole, since coloured its headings looked like the file's own, and a diff's added and removed lines are green and red.

Text can be selected past the rows in view. Pressed on the head of the M2 log's 23-line table and held below the preview, the preview scrolls a row every 30 ms, and what scrolls under the pointer is selected. Letting go after eleven rows (`<sel` marks a row drawn reversed):

```
┌Preview────────────────────────────────────────183-209/336┐
│| Bundle directory named `renamed-dir`, frontmatter `name:│  <sel
│actual-name` | shown as `actual-name` |                   │  <sel
…
│| ANSI escape sequence and a literal tab in a description │  <sel
│| control bytes dropped from the output |                 │  <sel
└──────────────────────────────────────────────────────────┘
```

copies all 36 rows of the table, 1,395 characters, from a head no longer in view. The wheel can turn during a drag and the selection takes in what it scrolls past; once let go, the highlight stays on its words while the preview scrolls.

## Pitfalls actually hit

Each is written up where the concept lives:

- [[integer-overflow]]: `*top -= …` expected to stop at 0 — two tests panicked, and a release build jumped to the last page; then a release build expected to panic. Settled in slice 2.
- [[borrowing]]: a method taken to lend only what it reads (slice 1, settled); *take the write borrow first* (slice 2); and, **not settled**, the body read instead of the signature — `self.current.push(…)` left out with the methods on `self`.
- [[option-and-match]]: `None` answering *no* to every question — M7's everyday reading of `None`, back through all three slices, and settled in slice 3 by writing `is_none_or` out as a `match`.
- [[state]]: **not asked again** — a `Spot` taken for a cell of the screen; 14 tests failed.
- [[statics]]: a `static` taken to be worked out as the program runs; and, **not settled**, `Instant::now()` against `Instant::now` — calling a function against handing it over ([[closures]]).

Twice the author's reply to a round of wrong answers was to change how the round went. After slice 2's review questions went 0 for 4, the choice offered was more questions or an explanation line by line, and the author took the explanation. After slice 3's review, with two gaps left, the author chose to move on. Both gaps are in *Left for later*.

The assistant's words steered answers three times. In slice 1, a question said only the third line of two snippets differed; it was the first, and the grading allowed for it. In slice 2 the drawing meant to answer *what is a `Spot`* went out half-written, and the reply was *"I don't follow"*. In slice 3, a question asked in which states a function *is called*, where what was being tested was a value: the wrong answer to it was traced, by a diagnostic question, to the wording.

What worked, again, was asking why before explaining more. Three diagnostic questions in slice 3 found three different reasons — one the author had already outgrown (`None`), one different from what the wrong answers suggested (the body of a method, not the order of borrows), and one missing idea (when a `static` is worked out) — and each was treated on its own.

## What measurement changed

**How much a preview hides.** Before any code, on this machine: 472 of 586 files have more lines than a 120 x 40 terminal's preview has rows, and the M2 log is 336 rows at the preview's width, of which 27 could be read before M8. Counted again as this log was finished: 482 of 596.

**How a selection should behave.** herdr's source was read before slice 2, since the author uses it daily. It keeps a selection by cells of the text, scrolls every 30 ms while a drag is held past an edge, and scrolls three rows a notch of the wheel; all three were taken. Two things were not: herdr also jumps three rows per row of distance the moment the pointer leaves, up to fifteen, and starts scrolling with the pointer on the pane's last row as well as below it. Here it is a row every 30 ms, starting once the pointer is on the border or past it.

**Whether ratatui's wrapping could go.** It had stayed on the preview as a safety net. Drawn across this machine's 585 files at widths 20, 38, 58 and 98, no row came out wider than its width — and the check can fire: at one column less it catches 13,499 rows at width 58. So the preview draws one line to a row, and a selection's rows are the file's own. Measured again as this log was finished, after slice 3 changed how code is cut: 595 files, no row too wide, and 14,070 rows at one column less; and after slice 5, which cuts a block of Markdown as one piece again: none too wide, and 14,095.

**Which colours.** Three ways were built into one binary and shown to the author in a real terminal: syntect's own `base16-ocean.dark`, colours fixed whatever the terminal; a table of six kinds of token in the terminal's palette, with the rest of the code yellow as before; and the same table with the rest in the terminal's text colour. The author chose the last.

**What colouring costs.** The preview is drawn again after every key, and a highlighter cannot start in the middle of a block, so every drawing colours the whole file:

| slowest file, one drawing | before M8 | coloured | coloured, dependencies optimised |
|---|--:|--:|--:|
| release, width 58 | 6.3 ms | 30 ms | (a release build optimises them already) |
| release, width 20 | 7.0 ms | 30 ms | |
| `cargo run`, width 58 | 48 ms | 358 ms | 53 ms |
| `cargo run`, width 20 | 65 ms | 362 ms | 42 ms |

Width 58 is the preview in a 120-column terminal. The slowest file before M8 was cli-printing-press's changelog; coloured, it is a PDF skill's reference, whose 445 lines of code are the most of any file here, or at width 20 in `cargo run` a database schema of 250. With `[profile.dev.package."*"] opt-level = 3` ([[external-crates]]), `cargo run` comes back to within a few milliseconds of what it was — 53 against 48 at width 58, 42 against 65 at width 20 — so nothing is cached between drawings.

**Which regex engine.** syntect's default, Oniguruma, is C and needs a C compiler to build; its other, fancy-regex, is Rust. Timed on the same blocks, Oniguruma took the heaviest file in 13.5 ms and fancy-regex in 28.4. fancy-regex was taken, for M11's builds on other platforms.

**What gets coloured.** Counted as this log was finished, the parser finds 1,459 code blocks on this machine, and 897 name a language. 745 of those are coloured — 83%. `markdown` and `md` name 99 that syntect knows and that are left yellow by the author's choice after review (below); `text` names 21, `powershell` 15, `mermaid` 11 and `toml` 3; and 562 blocks name nothing. All of those are yellow. (Slice 3's commit counted 1,429 blocks and 827 coloured, before this log and its pages were written and while Markdown was still coloured; slice 4 counted 844.)

**Lines in pieces.** The parser hands a code block over in pieces, and a highlighter needs whole lines. A tab in a list item's indentation splits one in two, so a line is gathered first and copied only if a second piece is added to it ([[owned-vs-borrowed-pairs]]). Before slice 3 was committed, a count found none of the 13,960 lines of code here in two pieces. Review found the count wrong: a file whose lines end in CRLF hands each break over on its own, after its line, and the empty piece before the break was joined on — which copied the line. 9,228 of the 13,960 were copied, all in the 320 files here with CRLF line ends. Nothing is joined to an empty piece now, and none is.

**Where a long line of code breaks.** Coloured, a line is many pieces, and a piece that does not fit moves to the next row whole. So a line wider than the preview now breaks where its colours change, not in the middle of a name — at width 16, `    rootCmd.` / `Flags().BoolVar(` / `&asJSON, x)`, where it was `    rootCmd.Flag` / `s().BoolVar(&asJ` / `SON, x)`.

## Decisions

No record was written. Each choice below is cheap to reverse — a key, a colour, a line of `Cargo.toml` — and none needs context to be understood.

- **Chosen by the author**: code coloured in the terminal's palette, the rest of it in the text's own colour; after review, from four versions drawn side by side, a block of Markdown left yellow as code in no known language — coloured, its headings looked like the file's own — and a diff's added and removed lines green and red.
- **Chosen by the assistant and reported**: the wheel over the preview only, three rows; `Tab` round three panes, and Page Down and Up from any; how far each file is scrolled kept by its Entry's path, held to its last page by drawing; the title's `172-198/336` only when not every row shows, and some row does; the key hints unchanged; a selection kept by cells of the text; a row every 30 ms toward a pointer past the preview's edge, and none once the preview is as far as it goes that way; the wheel no longer lets go of a selection, a key still does; selected rows drawn again rather than read from a copy of the screen; ratatui's wrapping taken off the preview, the screen's own notes cut by the renderer as a file's lines are; syntect with fancy-regex and no themes of its own; dependencies optimised under `cargo run`; a code block in a language syntect does not know left yellow; Markdown told by the scope its syntaxes share, `text.html.markdown`, rather than by a list of names; nothing cached between drawings.
