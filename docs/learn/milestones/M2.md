# M2 — Domain model and frontmatter

> Roadmap: M2

## What was done

The five hand-written counts became a table of `Source` values, each carrying a **Walk** that says what one Entry is inside that source — a Markdown file, a Bundle directory, or a Markdown file anywhere below. The project rows stopped being special-cased code and became two more rows in the same table. Every Entry then reads the YAML frontmatter of the file that describes it (itself, or the Bundle's Lead) for a name and a description.

## Pitfalls actually hit

- [[structs]]: with the tuple array replaced, the loop **body** still spoke the tuple's language. Three errors, one cause — `name` had to become `src.name`.
- [[structs]]: the compiler offered `use std::thread::Scope` for a missing `Scope` type. It matched on the name alone; taking the suggestion would have compiled and meant something unrelated.
- [[enums-and-data]]: the first names for the traversal rules were `entries`, `bundleDirs`, `LeadDirs`. `entries` distinguished nothing (all three produce Entries), `LeadDirs` was `BundleDirs` under another name, and two of the three failed the casing lint.
- [[impl-and-methods]]: `bundle_dirs` was written with `lead: Option::None` hard-coded, so **every** Bundle claimed to have no Lead while all eight on this machine have one. Nothing failed, because nothing read the field yet; the only signal was `warning: field lead is never read`.
- [[vec]]: turning `count_md` (returns `usize`) into `md_files` (returns `Vec<Entry>`) stalled on where the return value comes from. Same accumulator, different type — and a block's last expression, written without a semicolon, is its value.
- [[str-scanning]]: the demo written to show `&s[..10]` panicking on Korean text **did not panic** — byte 10 was a boundary by luck. The real panic needed `&s[..11]`. Reasoning from the first run would have produced the opposite conclusion.
- A missing closing parenthesis in `PROJECT (outside any project` survived several runs, because that branch only executes outside a repository. Branches that rarely run are not checked by running.

## What measurement changed

**The walk table fixed three wrong counts and kept two right ones.** With every source counted by a bare `read_dir().count()`, a planted `stray-notes.txt` under `skills` and an extensionless `README` under `rules` were both counted (3 where 2 was correct), and moving the project rows into the table temporarily broke them too (`root md` 13, `docs` 2). After the Walk column: 2, 2, 3, 16.

**The unclosed-frontmatter guard was sized, not decided, by measurement.** Of 585 Markdown files across `~/.claude`, `~/.agents` and two projects' `docs/`, 281 open with `---` and **0** fail to close. The guard went in anyway: without it the parser reads body lines as fields, which is a silently wrong description rather than a crash, and `CLAUDE.md` names malformed frontmatter as a normal case rather than an edge one.

**Quote stripping had to be narrowed before it was ever wrong.** No description among the Leads the source table reads ends with a quote without starting with one, so `trim_matches('"')` would have worked on them. It strips both ends *independently*, though, so a description that merely **ends** in a quoted phrase loses its closing quote — and two such descriptions already sit under `~/.claude`, one closing `...how the old code happened to implement it."` and another closing `..."sync Asana tasks"`. Only a matching pair is stripped.

**Block scalars are rare enough to have been missed by inspection.** Exactly one of the Leads uses `description: >`, and the first parser rendered it as the single character `>`. Neither `|` nor a chomping indicator appears in any file the source table reads — but `|` is not hypothetical: four agent definitions under `~/.claude/plugins` use `description: |`, in a directory this program does not scan today and a config file could add tomorrow. All four forms are covered by one rule rather than a list of four, because a list would have let the other three through silently.

**Naming tree entries by file stem is good enough for now.** A neighbouring repository's `docs/` holds 80 Markdown files with **0** duplicate stems, so the collision that would justify carrying relative paths does not exist yet.

**One Bundle in eight is a symbolic link.** `~/.claude/skills/grill-with-docs` resolves to `~/.agents/skills/grill-with-docs`, which is the only collision among the eight. It is now visible on screen, which is what M1 was waiting for before deciding — see [ADR-0005](../../adr/0005-sources-report-their-own-directory.md).

## Decisions

[ADR-0005](../../adr/0005-sources-report-their-own-directory.md) — a Source reports its own directory; Entries are never merged across Sources. **Walk** was added to [`CONTEXT.md`](../../../CONTEXT.md), together with the resolution that ADR-0003's prose "traversal rule" names the same thing.

## How it was verified

Two fake home directories and thirteen deliberately broken Bundles, all run through the actual binary rather than through a copy of the parser:

| Planted | Result |
|---|---|
| `stray-notes.txt` in `skills`, extensionless `README` in `rules` | not counted |
| empty `skills` directory vs absent `rules` directory | `0` vs `(missing)` |
| repository with no `docs/` | `(missing)` |
| Bundle with no `SKILL.md` | listed, no description, no crash |
| Bundle directory named `renamed-dir`, frontmatter `name: actual-name` | shown as `actual-name` |
| frontmatter with no closing `---` | ignored; body not read as fields |
| 0-byte file, file with no frontmatter | no name, no description |
| `description:` with nothing after it | empty description, distinct from absent |
| `description: He said "no"` | closing quote kept |
| `description: "quoted value"` | quotes stripped |
| `description: >` and `description: |` blocks | joined into one line |
| `description: >-` (chomping indicator) | same |
| block followed by another key | block ends, the key is still read |
| blank line inside a block | skipped, block continues |
| CRLF file | parsed |
| byte-order mark before the opening `---` | frontmatter still read |
| tab-indented continuation line in a block | value gathered |
| `name:` with an empty or whitespace-only value | the filename is kept |
| `.MD` and `.Md` extensions | counted |
| a directory named `oops.md` | not counted |
| ANSI escape sequence and a literal tab in a description | control bytes dropped from the output |

All exit 0.

Two notes on the fixtures themselves, both learned the hard way here.

Setting `USERPROFILE` to an **empty string does not isolate the program** from the real home directory: `env::home_dir` falls back to the profile path the OS reports, so a fixture path that fails to build produces a plausible, successful, entirely wrong run against live data. That happened once during this session.

And a fixture that another process can reach is not a fixture. While the reviewers ran, one of them wrote into the same scratch directory these fake homes live in, and a regression re-run measured a directory that had changed underneath it. The only reason it was caught is that the numbers were impossible for the input that was supposed to be there.

## What review caught

Two reviewers went over M2 before the commit — one attacking the program, one re-measuring every number in the documents — both required to reproduce their claims rather than assert them.

The source reviewer found **six ways to produce a wrong answer at exit 0**, all fixed:

| Input | Was | Now |
|---|---|---|
| byte-order mark before the opening `---` | the whole block ignored, name and description lost | read |
| tab-indented continuation inside a `>` block | description silently empty | gathered |
| `name:` with an empty value | the row lost its name entirely and could not be identified | filename kept |
| `.MD` or `.Md` | silently uncounted | counted |
| a directory named `oops.md` | counted as a file Entry | skipped |
| an ANSI escape inside a description | written to the terminal verbatim | control characters dropped |

The last is why `short` now filters as well as truncates. This program prints text out of somebody else's files, and an escape sequence in a description can move the cursor or recolour the terminal.

The documentation reviewer found four claims that did not hold, and **three of them made the argument stronger once corrected**: `|` blocks and descriptions ending in a quote both do occur under `~/.claude`, in directories the source table does not read — which is a better reason to handle them than "the corpus has none" ever was. The fourth was a compiler `help:` line that had been paraphrased instead of copied.

Three further reports were declined, with the reason recorded rather than the code changed:

- A YAML `#` comment is not stripped from a value. Stripping it would cut any description legitimately containing ` # `, and no Lead uses a comment.
- Truncation can still split a multi-codepoint grapheme — an emoji ZWJ sequence, or a base character plus a combining mark. `short` promises character-boundary safety, which holds; grapheme safety was never claimed and needs a dependency.
- An empty `USERPROFILE` falling back to the real home is `env::home_dir` behaving as documented on Windows, not a defect here.

## Left for later

- A junction cycle inside `docs/` still inflates the count silently, and one pointing outside the project still escapes it. `md_tree` follows links, and nothing tracks which directories have already been visited. -> M3
- **A Bundle whose directory is a dangling link disappears from the count entirely.** `bundle_dirs` skips anything `is_dir()` denies, and a link whose target is gone answers `false`, so no row is produced at all — not even the `-` that a Bundle with a missing Lead gets. This is silent *under*-counting, the opposite direction from the junction problem above, and it is not academic: one of the Bundles on this machine really is a link. Telling "not a directory" apart from "cannot tell" needs the error rather than a boolean. -> M3
- An entry name longer than the 32-character column pushes that row's description out of alignment. `{:<32}` is a minimum width, and only the description is truncated — deliberately, since shortening a name would hide the identity the tool exists to show. -> M5
- `(missing)` is decided by `is_dir()`, so a directory that exists but cannot be read reports `0` rather than saying so. Telling those apart needs the error, not a boolean. -> M3
- The `.unwrap()` calls inherited from M1 are untouched, and `md_files` added one more (`item.unwrap()`). -> M3
- There are still no automated tests. Every check in this milestone was a fixture run by hand. -> M3
- Entries from a `MarkdownTree` are named by file stem, so two files with the same name in different subdirectories would be indistinguishable. -> M4 or M5
- Showing that two rows are the same file (the symlinked Bundle) is deferred, not rejected. -> M5
- `Frontmatter::none()` is what `#[derive(Default)]` gives for free once traits arrive. -> M4
- `Source::new` takes `&str` and copies. A config file hands over an owned `String`, which will want `impl Into<String>`. -> M10
- `session-seal` is still identified as a project root and still shows nothing, because its documentation lives outside the source definitions. -> M10
