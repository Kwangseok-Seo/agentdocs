# M6 — Markdown in the preview

> Roadmap: M6

## What was done

The preview now draws the selected file as Markdown. Headings are bold and cyan and keep their `#` marks; bold, italic, struck-out text and inline code are styled; a link shows where it points after its text. Lists keep their bullet's indent on every row they wrap onto, quotes keep their bar, code blocks keep their lines, tables are drawn as a grid when they fit and as one block per row when they do not, and frontmatter loses the lines that fence it. The listing changed too, where M5 left it: it measures in columns rather than characters, so a Korean description no longer prints twice its room, and a name or description loses what takes no room of its own — a right-to-left override, a zero-width space — as the screen's names now do as well.

## Pitfalls actually hit

Each is written up where the concept lives:

- [[lifetimes]]: a lifetime read as how long something runs — `&'static str` for the file's text, and a lifetime mistake predicted to be a panic at run time; `<'a>` declared on `Renderer` and not used in its field; `links` missed as a borrow; a literal expected to be copied into rows of file text, and in review a `Vec<Span<'static>>` holding file text expected to compile.
- [[slices]]: the line break taken for the start of the next line (`find` for `rfind`, `i` for `i + 1`); `"".strip_suffix('\n')` expected to be `Some("")`; `..colon` leaving the colon in neither half; and, in slice 4, a slice taken for a copy three times in one round.
- [[owned-vs-borrowed-pairs]]: `Cow` — four wrong answers in a row across slices 2 and 3.

What settled `Cow`, and the slice taken for a copy, was the same in both: not printed addresses, not the 16 bytes of a `&str`, but a drawing of what points at what — boxes and arrows for `Cow`, bytes numbered under the text with an arrow from each piece for slices. After each drawing, the review questions were right.

The assistant's own: E0599, a method whose trait was not in scope, came back in the assistant's code in slice 1 — the pitfall [[traits]] records from M5.

## What measurement changed

**What the corpus uses.** Before any code, this machine's 558 Markdown files were counted by construct, and the renderer was built in that order:

| construct | files | |
|---|--:|--:|
| headings | 556 | 100% |
| inline code | 547 | 98% |
| bold | 524 | 94% |
| lists (132 of them nested) | 467 | 84% |
| tables | 300 | 54% |
| code blocks | 288 | 52% |
| frontmatter | 233 | 42% |
| links / italic | 230 / 229 | 41% |
| quotes | 125 | 22% |

**What the parser costs.** pulldown-cmark with its default features off: three crates to compile, two of them new to `Cargo.lock`, and all 558 files — 6.1 MB — parsed in 99 ms, exit 0. Its counts agreed with Python's where both could see the same thing — 233 frontmatter blocks each — and came within two for tables, 628 against 626.

**How much is borrowed.** Of 126,554 pieces of text the parser handed back, 126,552 were slices of the file. Of 352,874 byte ranges, none began or ended inside a character, which is why cutting the file at the parser's ranges is safe where cutting at a counted byte is not ([[slices]]). 315 of the 558 files end their lines with `\r\n`, so the renderer's tests carry `\r\n` cases beside the `\n` ones.

**Why the renderer wraps.** Of 25,072 list items, 92% are wider than a preview in a 100-column terminal. ratatui's wrapping cannot put a bullet's indent in front of the rows it wraps onto, so the renderer cuts its own rows. That also ended M5's border defect, whose cause turned out to be ratatui's word wrapping: a word ending in a wide character reached one cell past the edge. The regression test fails when ratatui wraps again.

**What a table can be.** 628 tables; the widest row of each is 125 columns at the median. 31 fit a preview in a 120-column terminal, 296 fit one twice as wide. The author chose: a grid when it fits, one block per row when it does not. Four tables have a `|` inside backticks — one of them in this repository's M2 log — and the parser divides the row there and drops the cells past the head's count, with what they say. Those four are shown as written.

**Whether anything goes missing.** After each of slices 1–3, the letters and digits of every file were compared with what the renderer drew of it — from slice 2, at widths 38 and 58, and after slice 3 at 5000 too, so that no table repeats a heading, which could hide a loss. The only differences are HTML entities such as `&lt;` decoded outside code, as CommonMark says. The check was itself checked: with inline code dropped on purpose, it flagged 484 files. The largest file, 142 KB, renders in 16 ms in a debug build.

**What takes no room.** In the 540 files counted for slice 4 — the same roots as before, walked afresh: 45 of U+FE0F, the mark that makes `⚠` an emoji, and 8 zero-width spaces, all in bodies; none in a name or a description. Dropping every character of no width would have taken the 45 off their signs. The rule chosen is ratatui's own for the preview: leave out a *grapheme* — a character with whatever joins it — that holds a control character or takes no room.

**What the listing's width was.** In `cli-maker`, counting characters had let a row reach 108 columns in a design of 82, and a matched line 112. Counting columns: 82 and 72. Of the three baseline listings, the 33 lines that changed all hold a wide character; every other line is byte for byte M4's.

**What capturing screens found.** Capturing the samples above showed `: 독자` for a column headed by nothing, and a link's `(` left at the end of a row with its address on the next. The second was general: the renderer measured each styled piece as a word of its own, so `**bold**,` could break between the bold and the comma. Rendering the whole corpus at 38 and 58 before and after the fix, 1,080 renderings in all:

| change | renderings |
|---|--:|
| only where rows break — the text, spaces and quote bars aside, identical | 759 |
| a bare `: ` gone (rows starting with it: 126 → 2, both text of the file) | 31 |
| anything else | 0 |

No row is wider than its width, measured with the renderer's own function. That count was checked on a renderer broken on purpose, where it found 107.

**How a line of code wraps.** Review found a line of code whose first word did not fit behind its indentation: the word moved down whole and left the indentation alone on a row of spaces. The reviewer suggested cutting every line of code where the row ends, as a terminal does. That and a smaller rule were both rendered over the corpus — 583 files at widths 18, 38, 58 and 98, 2,332 renderings — counting the rows of nothing but spaces that wrapping itself made:

| rule | a line's first row left with only spaces | later rows with only spaces | renderings changed |
|---|--:|--:|--:|
| cut every line of code where the row ends | 203 | 426 | 1,022 |
| wrap code as prose, but cut a word rather than move it off a row that holds only spaces | 2 | 0 | 198 |

Cutting at the row's end keeps a deep indentation as rows of spaces, cuts a template written inside a code fence in the middle of its words, and starts a row with the space it cut at. The second rule was taken. Its last two rows were indentation exactly as wide as the row, closed by giving spaces a column of room after them; and a space inside a code span's backticks next to the text's own now makes one run, not two. With those, against the renderer before slice 6, 199 renderings changed: 25 only lost rows that showed nothing, 87 rows in all; 1 no longer starts a row with a space; and in 173 words break in new places, from a word that followed nothing but spaces and is now cut behind them. No letter was lost, and no row passed its width. The price, as one of the 173 shows: a title centred in an ASCII drawing by 35 spaces is cut after `OUT` at width 38.

**What a long line costs.** The old cut measured what was left of a piece again for every row it made. On one line with no spaces, in a release build:

| length | before | after |
|--:|--:|--:|
| 20 KB | 1.73 ms | 0.46 ms |
| 100 KB | 38.73 ms | 1.81 ms |
| 400 KB | 634.93 ms | 7.25 ms |

Only a run without spaces is cut this way, and the longest on this machine is 206 characters — a table's line of dashes — so no file here was slow. A file that is one long run, such as minified JSON saved as `.md`, would have been.

## Decisions

No ADR. One is written when a decision is hard to reverse, would surprise a reader without its context, and was a real trade-off — all three at once. Nothing here is hard to reverse: every choice lives in one module and is undone by changing that module. The one that would surprise a reader — that the renderer cuts its own rows rather than leave them to ratatui — keeps its reasons where a reader meets it, in `wrap`'s doc comment.

- **The parser**: pulldown-cmark, with the renderer written here — the author's choice.
- **The renderer cuts its own rows**, for the indents and the border above. ratatui's wrapping stays behind it as a net for a row it would count wider.
- **A line of code wraps between words, as prose does**, and anywhere a word follows nothing but spaces it is cut rather than moved down — chosen by the assistant over cutting every line at the row's end, on the counts above, and reported.
- **Chosen by the author**: a table as a grid when it fits and as blocks when it does not; frontmatter without its fences, keys cyan.
- **Chosen by the assistant and reported**: headings keep their `#`; a link's address follows its text, dimmed, and an address written as a link is not said twice; `<cli>` and other words in angle brackets stay text, though CommonMark reads them as HTML; HTML is shown as on disk; a blank line only where the file has one; bullets `•` `◦` `▪` by depth; a numbered list counts from its first number; a quote's bar on every row; code blocks without their fences, in yellow, a tab as four spaces; a column headed by nothing shows its cells alone.
- **What takes no room is left out by grapheme**, as ratatui leaves it out of the preview, and the listing measures in columns. The listing's byte-for-byte baseline, kept since M4, was broken on purpose: new hashes below.

The existing records were checked against the new surface: rendering only draws ([ADR-0001](../../adr/0001-read-only-viewer.md)); [ADR-0008](../../adr/0008-screen-for-a-bare-command-at-a-terminal.md) says where the listing goes, not what bytes it holds; `CONTEXT.md` needed no new term.
