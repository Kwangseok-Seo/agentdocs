# M12 — Every Markdown file in a project

> Roadmap: M12. Asked for after M11 by the author, using the tool: a repository does not always put its Markdown under `docs/` or `.claude/` — some of it sits at the root, some in a directory made for one piece of work — and the screen showed none of that. Done without quizzes, at the author's request, as M10 and M11 were.

## What was done

A project's block is two Sources now, where it was the root's own files and `docs/`: `root md`, every Markdown file below the root, and `.claude`, the root's `.claude/` ([ADR-0015](../../adr/0015-a-project-is-every-markdown-file-below-its-root.md)). What a project's `.gitignore` files leave out is passed over, by every Walk; a directory named with a dot still is. The repository the author named first:

```
$ cd ~/projects/review-reflag-study && agentdocs | more     # before: root md:3, docs:(missing)
PROJECT C:\Users\adman\projects\review-reflag-study
  root md:421
    CLAUDE                           -
    ...
  .claude:(missing)
```

Across this machine's projects, the listing before and after, with the binary installed from v0.1.0 and the new one:

| Project | Before | After | Left out by its `.gitignore` |
|---|---|---|---|
| review-reflag-study | `root md:3` | `root md:421` | (not a repository) |
| session-seal | `root md:1` | `root md:351` | (not a repository) |
| cli-printing-press | `root md:7` `docs:260` | `root md:316` `.claude:0` | — |
| ai-gold-backtest | `root md:3` `docs:29` | `root md:54` `.claude:20` | 15 `out/*/INVALID.md`; each run's `summary.md` is kept in git, and shown |
| agent-guideline | `root md:3` `docs:2` | `root md:16` `.claude:33` | 14 under `routines/_candidates/` and `_sub_agent_candidates/` |
| ai-gold-trade | `root md:3` `docs:15` | `root md:18` `.claude:87` | — |
| kiwoom-auto-trade32 | `root md:3` `docs:6` | `root md:10` | 5 in `kiwoom32/Lib/`, a Python environment |
| review-loop-bench | `root md:1` | `root md:25` | 6,812 benchmark results under `results/` |

In every one of the fourteen repositories here, `root md` is the number of Markdown files outside a dot-directory less the number `git check-ignore` names. `.claude` is shown whole whatever the root's `.gitignore` says, which in four of them keeps all or most of it out of git.

On the screen, `root md` opens onto the root's directories as `docs` did onto its own; in cli-maker, `root md:83` opens as `CLAUDE`, `CONTEXT`, `▸ docs/` and `README`.

Watching changed with it. Each directory a Walk read is watched alone, where a tree's directory was watched with everything below it: watched that way from a project's root, `.git/` and every build directory would be watched too.

## Concepts picked up here

- [[lifetimes]] — a borrow of what a function made cannot be handed back inside what it returns, E0515 through a struct rather than a bare `&`: why the `.gitignore` rules a Walk carries down are copied rather than borrowed.

## How it was built

- **`Ignored`** in `source.rs` holds the rules of the `.gitignore` files a Walk has met, nearest last; `and` adds a directory's own, and `ignores` asks them from the nearest out, the first that matches deciding. Each of the three Walks starts with an empty one and adds its own directory's; `described`, which every Walk passes each item through, leaves out what it ignores — one filter for all three, rather than one per Walk.
- **The matching is the `ignore` crate's** — ripgrep's, `Gitignore::matched` — rather than our own reading of the pattern language. Version 0.4.30: the newest, 0.4.33, needs Rust 1.88, and cargo picked the newest version `rust-version = "1.87"` allows. Six crates came with it (`ignore`, `globset`, `bstr`, three of `crossbeam`), and `THIRD-PARTY-LICENSES.txt` went from 67 licences and 2,439 lines to 69 and 2,501, with nothing to add to `about.toml`.
- **`Walked::dirs`**: every directory a Walk read, whether or not it found anything there. `Source::watched` returns those, and the links standing in for Bundles; the flag that said whether to watch below a path is gone, and `rewatch` watches every path alone.
- **The loop asks what to watch after `tick`**, which is where the Sources are read again — below, under Pitfalls.

## Pitfalls actually hit

- **What to watch, worked out before what it follows was read.** A directory that appeared was only watched once the loop came round, after the next message; a file written into it was that message, and was never heard. Found by driving the real screen, not by a test — [[event-loop]].
- **A test fixture that could not catch the mutation it was written for** — a `.gitignore` line naming a directory and nothing in it ([[testing]]).
- **The count first given to the author was wrong.** Asked whether a project's `.gitignore` should be honoured, the author was shown how many Markdown files each would hide, from a Python script that asked `git check-ignore` — 36 in ai-gold-backtest. Its paths were written to git in text mode, and on Windows each `\n` went out as `\r\n`: git read `summary.md\r`, which the `!out/*/summary.md` line does not name. The real number is 15, found when the new binary listed 54 where the table said 33. The first explanation given for the gap, the backslashes in the script's paths, was wrong too: with forward slashes the count stayed 36. Written as bytes, it is 15.
- **A change one level down is heard on Windows.** The test that nothing below an ignored `target/` or a `.git/` is heard first changed a file directly inside `.git/`; Windows reported `.git` itself as modified on the root's watch. The root was watched alone before this milestone as well, and heard the same. It was an assertion about the system rather than the code, as one in M9 had been ([[testing]]); the test changes files two levels down instead, which is what watching alone decides.
- **A script that added the new field to every `Walked { … }` literal in the tests** matched `-> Walked {` in a function's signature too, and wrote the field into the end of the function's body. The build said where.

## What measurement changed

- **Most repositories here keep `.claude/` out of git.** In four of them, `.claude/` held 87, 91, 28 and 20 Markdown files that a `.gitignore` read from the repository's top would hide. The author, shown the counts, chose `.claude` shown whole; reading only the `.gitignore` files met on the way down is the rule that gives that without naming `.claude` anywhere.
- **What a tree from the root would watch, watched whole**: 1,857 directories in this repository (`target/` 1,591, `.git/` 256), 26,298 in review-loop-bench, 2,928 in trip-guide (its `.venv/`). Watched where each Walk read: 8 here, 16 in review-loop-bench, 671 for all of `~/projects`.
- **`Rc` was measured against copying, and lost nothing but its reason.** Walking all of `~/projects` took 373 ms with the rules shared through `Rc`, 378 ms with them copied — the median of five each. The code copies.
- **Run from `~/projects`**, a workspace with no marker of its own, the block is the whole workspace: 1,489 files, 0.8 s and 234 MiB to list. Without the `.gitignore` files it was 8,339 files, 1.8 s and 267 MiB.

## Decisions

- [ADR-0015](../../adr/0015-a-project-is-every-markdown-file-below-its-root.md): the project's Sources, the `.gitignore` files a Walk reads, and what is watched. Banners on ADR-0002 (its list of project sources) and ADR-0011 (its first sentence on what is watched).
- By the author: `.gitignore` honoured; `.claude/` shown whole; no quizzes.
- The tree from the root keeps the name `root md`, so an `order` naming it still works. One naming `docs` now makes its config file unusable, and says so.

## How it was verified

- **Tests**: 358 and 10 on Windows, 357 and 10 on Linux (in a container, as a user who is not root). Nine new — six on `.gitignore` files, two on what is watched and what is heard, and one running the binary over a project with a `.gitignore` — and three on watching rewritten for paths watched alone. `cargo clippy --all-targets -- -D warnings` says nothing on either.
- **Mutations**: ten on the `.gitignore` rules and the source table, ten caught after the fixture above was fixed; eight on watching, eight caught.
- **Against git**: the comparison in the table above, repository by repository.
- **The screen, driven**: started in a console of its own, read from its screen buffer, a directory made and a file written into it a second and a half later — `root md:2`, then `3`; a file written below an ignored `target/`, still `3`; `q`, exit 0. Three runs of three; with the loop's old order, none of three.

## Left for later

- **macOS has not run the tests.** Watching each directory alone is new there, and FSEvents is the backend that differed in M11. CI runs them on the next push.
- **A project root below its repository's top** — a package with a `CLAUDE.md` of its own in a larger repository — is walked without the top's `.gitignore`, so a `node_modules/` named only there is walked. None is on this machine.
- **Case.** Git on Windows and macOS matches `.gitignore` patterns ignoring case (`core.ignorecase`); here they are matched as written. A `.gitignore` saying `RESULTS/` leaves `results/` out for git and not here. What differs is shown, never hidden.
- **`.claude/worktrees/`**, where Claude Code keeps a checkout per isolated agent, would be listed whole under `.claude` while one is there.
- **A directory one level below a watched one**, reported changed by Windows when something inside it changes — `.git` at a git command — has every Source read again, as it did before this milestone. Walking a project's `root md` once took 8 ms for this repository and 57 ms for cli-printing-press, the largest repository here.
